# SlopAMP tests

End-to-end tests that start SlopAMP in Electron and drive it with Playwright. They were written for Linux under
`xvfb-run` and use a throwaway HOME for every run, so your own SlopAMP profile and downloads are never touched.

## Running

1. `npm i playwright` (or have it on `NODE_PATH`) and an Electron binary.
2. The app folder needs FFmpeg in `vendor/ffmpeg/linux` (as for a dev checkout; since 3.2.0 `bin/` + `lib/`, which
   `build/fetch-linux-tools.sh` sets up along with Electron in `vendor/linux-tools/electron-linux/electron`).
3. `tests/make-media.sh`
4. `xvfb-run -a node tests/library-preview.js`

The tests start SlopAMP with `--ozone-platform=x11` and without `WAYLAND_DISPLAY`, so on a Wayland desktop they stay on
xvfb's display (3.2.0). They expect a machine that can't reach X or YouTube: on one that can, run them in a network
namespace without network, e.g. `unshare -rn sh -c 'ip link set lo up && exec xvfb-run -a node tests/size-limit-favorites.js'`
(otherwise SlopAMP marks the made-up YouTube ids "(unavailable)"). The tests marked "with libx264" need an ffmpeg that
has it on PATH (e.g. Ubuntu's `ffmpeg` package) to make their sample videos; the bundled LGPL build doesn't.

Settings (environment variables): `SLOPAMP_ELECTRON` (Electron binary), `SLOPAMP_APP` (app folder, default this
checkout), `SLOPAMP_TEST_MEDIA` (sample media, default `tests/media`), `SLOPAMP_TEST_OUT` (screenshots),
`N_BIG` (files in the big-Library check, default 1000). Each check prints `ok` or `FAIL`; the run ends with
`ALL OK` or the number that failed.

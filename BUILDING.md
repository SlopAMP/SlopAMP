# Building SlopAMP

Developer notes. The user-facing introduction is in [README.md](README.md).

## How it works

```
Electron (Chromium UI)  ── src/renderer/  index.html · winmgr.js · skins.js · app.js · panel.html
                                          skins/*.css · frame.css · style.css
   │  IPC (preload.js, contextIsolation + sandbox)
Main process            ── src/main.js     state, playlists, downloads index, media keys
   ├─ WindowManager     ── src/windows.js  where the windows are: snapping, docking, presets, saved layout
   ├─ Downloader        ── src/downloader.js  yt-dlp queue (one at a time, self-updating copy)
   └─ MediaServer       ── src/media.js    127.0.0.1-only HTTP server:
         /app/*   UI files (an http origin so the YouTube embed gets a valid referrer)
         /f/KEY   local file with Range support (MP4/H.264, WebM, MP3, FLAC, WAV, OGG, AAC)
         /s/KEY   FFmpeg live remux/transcode → fragmented MP4 (MKV, AVI, ProRes, WMV, HEVC, AC3…)
                  encoder auto-picked: NVENC → AMF → QuickSync → Media Foundation → OpenH264
         /v/KEY   subtitles converted to WebVTT
```

- **Windows** (1.3): the player, equalizer, video/visualizer and playlist are four real windows. `index.html` holds all the content; `winmgr.js` wraps each panel in a window frame, opens the other windows with `window.open('panel.html', id)` and moves their frames into them, then starts `app.js`. Same-origin windows opened this way share the player's renderer process, so `app.js` drives every window directly (one `<video>`, one AudioContext, the YouTube player and Butterchurn all keep working across windows). Rules for code in `app.js`:
  - find elements with `$` / `$$` (they search every window), not `document.querySelector`;
  - listen with `WM.onDocs(type, fn)` / `WM.onWins(type, fn)` for document/window events that should work in any window;
  - `<body>` classes go through `WM.body` so every window gets them;
  - popup menus open with `WM.popup(el, { doc, x, y, flipY, above })`: they live in a hidden always-on-top `popup` window so they can stick out of small windows. Dialogs (`showModal()`) open in their own `dialog` window the same way;
  - show/hide/roll up windows with `syncWindows()` (it calls `WM.setPanels`).

  `src/windows.js` (main process) owns the geometry: it moves windows for title-bar drags and the resize grip/edges (it follows `screen.getCursorScreenPoint()` until the mouse is released), snaps edges within 10 px to screen edges and other windows (edge to edge, never overlapping), moves the windows docked to the player along with it, moves windows docked underneath a window that grows, shrinks, appears or disappears, applies the Layout presets and Reset layout, and resets the layout when a window ends up off screen. The layout is saved in the state file under `layout`:

  ```
  "layout": { "version": 1, "skin": "default", "preset": "classic", "snap": true, "onTop": false,
              "windows": { "main": {"x":..,"y":..,"w":..,"h":..}, "eq": {...}, "video": {...}, "playlist": {...} },
              "heights": { "main": 171, ... } }
  ```

  `skin` is the chosen skin's id (see below); the lightning bolt and Reset layout never change it. `heights` are the on-screen heights (a rolled-up window is only its title bar). Which windows are open or rolled up is renderer state (`showVideo`, `showPlaylist`, `eq.panel`, `vis.panel`, `plShade`, `vidShade`). On the first 1.3 launch the layout is built from 1.2's `window` and `plHeight` keys.
- **Skins** (1.4): every colour, glow, border, background, font and size is a CSS variable. `src/renderer/skins/classic.css` is the default "SlopAMP Classic" skin and defines all of them; `style.css` (window contents) and `frame.css` (title bars, borders, resize grips, snap highlights, the popup/dialog windows) only use those variables, and the canvas drawings (clock, state icon, spectrum, EQ curve, BARS) read theirs with `WM.token('--name')`. The other skins (`skins/<id>.css`) are loaded after `style.css` and override what they change; they're generated by `build/skins/make_skins.py` (colour transforms of Classic plus hand-picked values and a few extra rules), so edit a skin there and re-run it. `src/renderer/skins.js` has the list of skins, switches them (it swaps one `<link id="skinCss">` in every window, then redraws the canvases) and builds the picker; the choice is saved as `layout.skin`. To add a skin: add it to `make_skins.py` and to `SKINS` in `skins.js` (with its preview colours). Window frames are built in one place (`FRAMES` / `buildFrame()` in `winmgr.js`). The only colour outside the skins is the main process's `backgroundColor`, which shows for a moment before the page paints.
- **State** (playlists, tabs, settings, download index, window layout) lives in `%APPDATA%\SlopAMP\slopamp-state.json`. The portable exe uses `SlopAMP Data\` next to the exe instead.
- **Downloads** go to `Downloads\SlopAMP\Video`, `\Audio`, and playlists to `\Playlists`. Every downloaded file is named `Title [VIDEOID].ext`, so SlopAMP can re-find copies from the folders alone.
- **Updates** (`src/updater.js`): at most once a day (10 s after launch) the main process asks `api.github.com/repos/SlopAMP/SlopAMP/releases/latest` for the newest release. The installed build downloads the `SlopAMP-Setup-X.Y.Z.exe` asset into `%TEMP%\SlopAMP-update`, checks its SHA256 against the `SHA256 (SlopAMP-Setup-X.Y.Z.exe): <hash>` line in the release notes, checks it again just before running it, quits normally (window closed, state saved, "quitting" in the log), and only then, from `will-quit`, runs `SlopAMP-Setup-X.Y.Z.exe /S /UPDATE /PID=<pid> /D=<folder SlopAMP runs from>` (so a custom install folder is kept; `/D=` must stay last and unquoted). In `/UPDATE` mode the installer waits for that process to exit (it writes its steps to `slopamp.log` as `installer: …`), keeps the desktop-shortcut choice, and reopens SlopAMP. Before installing (and uninstalling), the installer looks for any SlopAMP window or SlopAMP.exe process, including hidden ones and the portable exe's copy in `%TEMP%`. It asks them to close (WM_CLOSE), and ends them with `taskkill` if they're still there after 10 s. Interactive runs ask the user first. A release without that line, or without the Setup asset under `https://github.com/SlopAMP/SlopAMP/releases/download/vX.Y.Z/`, is refused. The portable exe (`SLOPAMP_PORTABLE=1`) and dev runs only open the release page. Settings live under `update` in the state file: `mode` (`auto`/`notify`/`off`), `lastCheck`, `skipped`, `dismissed`, and `pending` (the version being installed, so the next launch can show "Updated to X").
- **Visualizer:** `src/renderer/vendor/` holds the Butterchurn bundle and presets. `build/butterchurn/build.sh` rebuilds them from the upstream sources. Preset equations are precompiled so the app's Content-Security-Policy can forbid `eval`.

## Developing

On Windows with Node.js installed:

1. Put FFmpeg in `vendor\ffmpeg\win32\` (`ffmpeg.exe`, `ffprobe.exe` and DLLs from a [BtbN LGPL shared build](https://github.com/BtbN/FFmpeg-Builds/releases)).
2. Optionally put `yt-dlp.exe` in `vendor\ytdlp\win32\` for the Download button.
3. Run `npx electron@41.2.0 .`

## Building the installers

The release build runs on Linux (or WSL) and uses Wine only for `rcedit`:

```
TOOLS=/path/to/tools bash build/build-win.sh
```

`TOOLS` must contain:

- `electron-win/`: unzipped `electron-v41.2.0-win32-x64.zip` (from Electron's GitHub releases)
- `ffmpeg-win/<dir>/`: BtbN `ffmpeg-master-latest-win64-lgpl-shared`
- `ffmpeg-linux/`: the matching linux64 LGPL build (used to read the version)
- `ytdlp/`: `yt-dlp.exe`, plus `yt-dlp_linux` (used to read the version)
- `nsis/`: electron-builder-binaries `nsis-3.0.4.1`
- `rcedit-x64.exe`, plus a Wine install

`build-win.sh` also writes `dist/uninstall-files.nsh` with `build/make_uninstall_list.py`: one `Delete` per installed file and an `RMDir` (empty folders only) per folder. The uninstaller uses only that list and never deletes the install folder recursively, because it may be shared. `installer.nsi` refuses to compile without it.

Outputs go to `dist/`: the app folder, `SlopAMP-Setup-<version>.exe`, `SlopAMP-Portable-<version>.exe` and a zip.

## Visualizer files

`src/renderer/vendor/butterchurn.min.js` and `src/renderer/vendor/butterchurn-presets.js` are committed, so a fresh clone runs without extra steps. To regenerate them from the upstream Butterchurn sources, run `bash build/butterchurn/build.sh`. You need git, python3 and npx. The script pins the exact upstream commits.

## Testing the updater

`bash build/make-update-test.sh` (after `build-win.sh`) makes `dist/update-test/`: three local release files (good, wrong SHA256, no SHA256 line) and a `.bat` for each, plus one for the portable exe. The installed-build `.bat` files find SlopAMP through the registry (uninstall `InstallLocation`, then `HKCU\Software\SlopAMP\InstallDir`, then the default folder). Each `.bat` starts SlopAMP with two environment variables:

- `SLOPAMP_UPDATE_TEST=<path to a release.json>`: read that file (same format as GitHub's release JSON) instead of GitHub, and check at every launch. The installer must be a plain file name next to it.
- `SLOPAMP_TEST_VERSION=1.1.9`: the version SlopAMP pretends to be, so the release counts as newer. Ignored without `SLOPAMP_UPDATE_TEST`.

The About box shows TEST FEED while these are set. They are not passed on to the installer, so the reopened SlopAMP is a normal run and shows "Updated to X".

## Releasing

1. Bump `version` in `package.json` and add a section to `CHANGELOG.md`.
2. Build with `TOOLS=... bash build/build-win.sh`.
3. Get the checksums: `cd dist && sha256sum SlopAMP-Setup-X.Y.Z.exe SlopAMP-Portable-X.Y.Z.exe`.
4. Create a GitHub release tagged `vX.Y.Z` (not a pre-release) and attach both exes. Write the notes in Markdown (the in-app "What's new" box shows headings, bullets, **bold**, `code` and links) and end them with one line per exe, exactly in this form:

   ```
   SHA256 (SlopAMP-Setup-X.Y.Z.exe): <64 hex characters>
   SHA256 (SlopAMP-Portable-X.Y.Z.exe): <64 hex characters>
   ```

   The auto-updater refuses a release whose notes have no `SHA256 (SlopAMP-Setup-X.Y.Z.exe)` line, or whose hash doesn't match the downloaded file. These lines are hidden from the "What's new" box.
